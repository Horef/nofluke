# src/nofluke/strategies/

Candidate-proposing strategies: the `Strategy` interface and `History` a strategy sees, the built-in random strategy,
the Optuna backend (`tpe`, `gp`), the Latin-hypercube design used for every study's first candidates, and the registry
(`get_strategy`) that maps a config's `strategy.name` to an implementation.

Folder rules: a strategy proposes one candidate from (history, rng, index) and draws only from the rng it is given;
the Optuna backend lives in its own module, is the only one that imports Optuna, and is imported lazily by the registry
(a missing package fails there with the extra to install).
